# Аварийный локальный администратор

Bootstrap выполняет оператор с доступом к Docker на сервере приложения, в интерактивном
терминале API-контейнера (UID10001 или root). Отдельной HTTP-регистрации и учётной записи
с паролем по умолчанию нет. Пользователь получает только роль `storage_admin`.

Из каталога проверенного релиза после миграций до head:

```sh
docker compose --env-file /etc/storage-console/production.env \
  -f deploy/compose/docker-compose.prod.yml exec api \
  python -m apps.api.user_auth.bootstrap --username storage-emergency
```

Команда дважды запрашивает пароль через скрытый ввод. Требуются минимум 16 символов и
не более 1024 байт UTF-8. Пароль не передаётся через аргументы, переменные окружения,
stdin pipe или файл. В БД хранится только Argon2id. Успех выводит `AUTH_BOOTSTRAPPED`;
ошибки выводят машинный код без входных значений.

Первый запуск создаёт явно указанную локальную учётную запись. Повторный запуск с тем же
именем меняет пароль и возвращает единственную роль `storage_admin`. Смена пароля отзывает
все её сессии в той же транзакции; проверка версии пароля при выдаче сессии отклоняет вход,
проверенный до ротации. В аудит записываются создание/ротация и фактическое изменение ролей,
без пароля и токенов. Состояние блокировки существующего пользователя сохраняется.

Имена нормализуются в нижний регистр и уникальны среди всех провайдеров. Выбирайте отдельное
аварийное имя, не совпадающее с AD-пользователем. LDAP-пользователь с совпадающим именем
не преобразуется в локального администратора. Каталог связывается по objectGUID; конфликт
имени при переименовании или пересоздании AD-учётной записи закрывает вход и требует
явного решения оператора, сохраняя старую идентичность и её историю.

Bootstrap изменяет данные БД, но не включает локальный провайдер в конфигурации. Для входа
нужны `local_enabled: true`, завершённые HTTP-сессии и HTTPS-доступ. Данный компонент не
заменяет ещё незавершённое подключение защиты к маршрутам и интерфейсу.
