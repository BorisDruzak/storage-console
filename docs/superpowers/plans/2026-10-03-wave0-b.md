# Wave 0B Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** PostgreSQL schema, versioned collector contracts, idempotent ingest/read API и конкурентный PostgreSQL worker.

**Architecture:** Collector authentication отделена от будущих user sessions. API валидирует versioned batch, проверяет scope collector/source, применяет записи и idempotency receipt в одной транзакции. Worker обрабатывает PostgreSQL jobs с SKIP LOCKED, retries и advisory locking; Web получает данные только через read API.

**Tech Stack:** Python 3.13, FastAPI/Pydantic v2, SQLAlchemy 2, Alembic, PostgreSQL 16, pytest/Ruff/mypy. Использовать существующий requirements.lock.

**Spec:** docs/tasks/wave0-b-backend.md; docs/spec/storage-control-plane-v0.1.md.

## Global Constraints

- Observe/diagnose/recommend, no live collectors, SSH/WinRM polling, remediation, document content or hardcoded departments.
- Все Required tables из задания Wave 0B создаются с полезными структурированными columns, constraints и relationships; пустые generic placeholder tables не являются реализацией.
- Canonical volume identity: source + persistent volume identity; aliases — отдельная history, не drive-letter primary key.
- Filesystem object unique: volume_id + file_id. Deleted object сохраняет last-known path.
- Timezone-aware UTC timestamps; versioned schemas и published OpenAPI.
- Ни missing, ни stale data не возвращаются как healthy.
- Public repository boundary сохраняется; использовать только synthetic fixtures.
- Execution в main и push разрешены пользователем.

## Review Focus

- Повторный batch с тем же ID и другим содержимым: конфликт, без скрытой потери данных.
- Два одновременных uploads и два worker process: нет duplicate processing.
- Ошибки authorization/schema/DB: без частичного ingest и credential leakage.
- Unconfigured/missing/stale source: UNKNOWN/freshness отличны от HEALTHY.
- Rename/delete и смена mount alias: canonical identity и path history сохраняются.
