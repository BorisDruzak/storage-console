# User authentication implementation plan

Spec: `docs/spec/storage-control-plane-v0.1.md` §6/25/35. Baseline:
`7b40e71e4b41c96569a9f4c2835a41b5e3f0441d`.
Use executing-plans inline, one fresh whole-scope review at the end.

Goal: product login/logout/me, secure PostgreSQL-backed sessions, CSRF and five roles;
AD/LDAPS-compatible provider plus documented local break-glass admin. Collector bearer
authentication remains independent. Complete this prerequisite before Wave1 management APIs.

## Design and rulings

The user authorized the canonical specification and inline execution/main publication.
This plan elaborates its existing authentication gate; it does not substitute gateway Basic
auth for sessions. No new execution-method/permission loop is needed for this approved scope.
GitNexus has no storage-console index (live checked); use source/contracts, no other index sync.

Persistent random opaque session tokens: only SHA256 hashes stored. Cookie
`__Host-storage_session`, Secure/HttpOnly/SameSite=Lax/Path=/, no Domain. Absolute lifetime8h,
idle30min, evaluated with PostgreSQL time. New session/token on every successful login;
logout revokes server-side and clears cookies. Role/disabled-user checks use current DB state.
Companion `__Host-storage_csrf` cookie Secure/SameSite=Lax/Path=/ readable by the UI; only hash
stored in session. State changes require matching cookie/header hash and exact configured
Origin. Login requires the same exact Origin and JSON; no anonymous credential form posting.
Never trust forwarded headers for origin/security or expose tokens in URL/localStorage/logs.

Five canonical roles: storage_admin,storage_operator,auditor,analyst,viewer. All can read the
existing metadata console. `manage_sources`/`manage_policy` require storage_admin;
`run_diagnostics` requires storage_admin/storage_operator. These permissions gate future
control endpoints; they do not enable remediation/filesystem access. Unknown roles deny.

Provider port separates local password authentication from directory authentication.
Local provider accepts only explicitly bootstrapped break-glass storage_admin. Argon2id
(argon2-cffi25.1.0,64MiB/time3/parallelism4), no default credential or public registration.
LDAP adapter uses ldap3 2.9.1, LDAPS636, required CA/hostname validation, TLS>=1.2,
bounded connection/search/bind, escaped account filters, no referrals, exactly one directory
subject. AD objectGUID is canonical subject. Group-to-role mapping is explicit; unknown or
unmapped membership cannot grant access. Nested AD group resolution must be explicitly
tested/documented; no silent assumption that direct memberOf is complete. A directory error
never falls back to local authentication. Provider choice is explicit in login request.

Auth provider configuration is a private validated JSON bind file readable only by API UID10001;
runtime must fail closed for invalid configuration. Production origin is canonical HTTPS DNS.
Real directory hostname/baseDN/service credential/group mapping are external prerequisites;
synthetic protocol tests cannot be reported as live AD acceptance. No credentials in public files.

Rate tickets are consumed transactionally before expensive credential verification: account
key is provider+normalized username SHA256, maximum5attempts/10min; global maximum100/10min.
No IP/user-agent/password persistence. Generic authentication failures avoid account enumeration.
Success/logout/role denial/rate denial/failure emit bounded audit records without secrets.

## Global constraints

- Python3.13 runtime, FastAPI0.142.2, SQLAlchemy2.0.x, PostgreSQL16; versions from repository lock.
- Context7 before external-library APIs; exact version behavior verified in source/runtime tests.
- RU/en-US catalogues; no hardcoded user-facing messages; full existing evidence freshness preserved.
- Web/MCP have no direct filesystem access, collector auth separate, no autonomous remediation.
- Production shares/live collectors/PVE mutation excluded. Internal topology/secrets stay outside Git.
